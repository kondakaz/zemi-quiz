準備1　GitHub アカウントと2要素認証

事前準備
何のためGitHub ＝ 記録をみんなで置く場所（Google ドライブのようなもの）。2要素認証は、パスワードのほかに、もう1つ確認する仕組み。
  1. GitHub アカウントを作る本名・学籍番号は、どこにも書かない。すでに本名のユーザー名で作った人は、先生に相談する
  2. GitHub の画面で、右上のアイコン → Settings → Password and authentication → Two-factor authentication → Enable two-factor authentication の順に進む
  3. スマホの認証アプリ（Google Authenticator や GitHub Mobile など）で、画面の QR コードを読み取る
  4. リカバリーコード（スマホをなくしたときの救済用の番号）を、必ず保存する
✓ できた印2要素認証がオンになり、リカバリーコードを保存した。

ターミナルの開き方と cd（準備2から使う）

事前準備
何のためターミナル ＝ 文字で命令を打つ画面。cd（シーディー）＝ フォルダに入る命令。
  1. Mac：⌘（コマンド）キー＋スペースを押して「ターミナル」と入力し、Enter
  2. Windows：スタートボタンを押して「PowerShell」と入力し、開く
  3. cd Documents で、「書類」フォルダに入る（準備8でも使う）
✓ できた印文字を打てる画面が開き、cd Documents を打てた。

準備2　Git と GitHub CLI（gh）を入れる

事前準備
何のためGit ＝ セーブする道具。gh ＝ ターミナルから GitHub を使う道具。

Mac

  1. ターミナルで git --version と打つ
  2. ツールの導入画面が出たら、「インストール」を選ぶ
  3. gh は https://cli.github.com から入れる

Windows

  1. https://git-scm.com の「Git for Windows」を入れる
  2. https://cli.github.com の gh を入れる
  3. 入れたあと、PowerShell を開き直す

あわせて Node.js（検査を手元で動かすための道具）も入れておくと便利。任意。入っていなくても、PR の検査で確かめられる。

✓ できた印git --version と gh --version を打って、どちらもバージョンが出ればOK。

準備3　Codex デスクトップアプリを入れる

事前準備
何のためCodex ＝ 作業を手伝ってくれる AI アシスタント。当日は、これに頼んで作業を進める。
  1. Codex デスクトップアプリを入れる
  2. サインインする
  3. 起動できる状態にしておく

このアプリで、あとの準備8で zemi-quiz フォルダを開き直す。頼むときの約束は、準備10で読む。

✓ できた印Codex が起動できる。

準備4（1）メールを非公開にして、noreply を控える

事前準備
何のためセーブ（commit）には、名前とメールアドレスが書き込まれて、公開される。だから先に、メールを公開しない設定にする。
  1. GitHub の画面で、右上のアイコン → Settings → Emails を開く
  2. Keep my email addresses private（メールアドレスを公開しない）を選ぶ
  3. 同じ画面に出る noreply アドレス（…@users.noreply.github.com の形。公開しても困らない代わりの住所）を控える
✓ できた印noreply アドレスを、メモに控えた。

準備4（2）名前とメールを Git に登録する

事前準備
何のためセーブ（commit）に書き込まれる名前とメールを、ニックネームと noreply アドレスにしておく。
  1. ターミナルで、名前はニックネーム、メールは控えたnoreply アドレスにして、次を打つ（ニックネームの決まりは、準備6）
  2. 本名や、ふだんのメールアドレスは入れない
git config --global user.name "ニックネーム"
git config --global user.email "控えた noreply アドレス"
✓ できた印git config --global user.name と git config --global user.email で、入れた値が出ればOK。

準備5　GitHub へのログインを済ませる

事前準備
何のためターミナルから GitHub を使えるように、先にログインしておく。
  1. ターミナルで gh auth login を打つ
  2. 質問は、矢印キーで選んで Enter。選ぶものは、次の4つ
    GitHub.comGit の操作は HTTPSGit の認証に GitHub のログインを使うか：Yesログイン方法：Web ブラウザ
  3. 途中で8文字のコードが出るので、控える
  4. ブラウザが開いたら、そのコードを貼って、Authorize（許可）を押す
✓ できた印gh auth status で、ログイン済みと出る。

準備6　ニックネームを決めて、先生に届ける

事前準備
何のためニックネーム ＝ あなたの名札。ファイル名とブランチ名に使う。
  1. ニックネームを決める（例：taro-k）
  2. 使える文字は、半角の英小文字・数字・ハイフンだけ
  3. ほかの人と重ならないものにする
  4. 先生に届けて、重複がないか確かめてもらう

同じニックネームの人がいると、あとから出した PR が止まってしまう。届けた名前は、当日は変えない。

✓ できた印先生に届けて、重複がないと確かめてもらった。

準備7　先生からの招待を承認する

事前準備
何のため先生の共有の棚（リポジトリ kondakaz/zemi-quiz）に、書き込めるようにする。
  1. 先生が、あなたの GitHub のユーザー名あてに、collaborator（共同作業者）の招待を送る
  2. 登録したメールに届く招待メールのリンクから開く（メールが見つからないときは、GitHub の通知からも開ける）
  3. Accept invitation（招待を受ける）を押す

招待には期限（7日）がある。早めに承認する。

✓ できた印承認すると、https://github.com/kondakaz/zemi-quiz に書き込めるようになる。

準備8（1）clone する

事前準備
何のためclone ＝ 共有の棚から、自分の PC に丸ごとコピー。
  1. まず cd Documents（cd ＝ フォルダに入る命令）で「書類」フォルダに入ってから、次を打つ
cd Documents

✓ できた印git status に On branch main（いま本番にいる）と出る。フォルダの中に index.html と questions/ がある。

準備8（2）Codex で開き直して、pwd をメモする

事前準備
何のため当日、cd で迷ったときのために、いまいる場所を控えておく。
  1. この zemi-quiz フォルダを、Codex アプリで開き直す
  2. pwd（いまいる場所を表示する命令）を打つ。出てきた場所を、メモする（当日、cd で迷ったときに使う）
  3. Codex アプリで作業フォルダを選ぶところで、その zemi-quiz フォルダを選ぶ

Windows で、OneDrive が「ドキュメント」を預かっているときは、場所が OneDrive の中になることがある。pwd の結果を、そのままメモする。

✓ できた印pwd の場所をメモした。Codex で zemi-quiz フォルダを開いた。

準備9　問題の文を考えてくる

事前準備
何のため当日は、メモを写すだけにして、30分に収める。
  1. 問題文
  2. 選択肢4つ（どれも違う文にする）
  3. 正解の番号（0から数える。1つ目が正解なら 0、4つ目なら 3）
  4. 解説（1〜2文）

テーマは自由。Codex に考えてもらってもよいが、答えが本当に正しいかは、自分で確かめる。公開されるので、本名・学籍番号は入れない。

✓ できた印この4つが、メモにそろった。

準備10　「読んでおく」と約束を読む

事前準備
何のため当日の説明を、短く済ませるために、先に頭に入れておく（3分）。
  1. 手順書の第1部の最後にある「読んでおく：なぜバージョン管理か／Git と GitHub」を読む
  2. 第3部の「Codex に頼むときの約束」を読む

なぜバージョン管理か
ファイル名で版を分けると、どれが最新か分からなくなる。Git なら、ファイルは1つのまま、セーブが積み重なる。

Git は道具、GitHub は置き場
Git は自分の PC の中で動くセーブ機能。GitHub は、そのセーブをみんなで置く場所。

✓ できた印2つとも、読み終えた。

まず自分で

・cd で「見つからない」：準備8でメモした場所（pwd の結果）に cd する
