準備1　GitHub アカウントと2要素認証

事前準備
何のためGitHub ＝ 記録をみんなで置く場所（Google ドライブのようなもの）。2要素認証は、パスワードのほかに、もう1つ確認する仕組み。
  1. GitHub アカウントを作る本名・学籍番号は、どこにも書かない。すでに本名のユーザー名で作った人は、先生に相談する
  2. GitHub の画面で、右上のアイコン → Settings → Password and authentication → Two-factor authentication → Enable two-factor authentication の順に進む
  3. スマホの認証アプリ（Google Authenticator や GitHub Mobile など）で、画面の QR コードを読み取る
  4. リカバリーコード（スマホをなくしたときの救済用の番号）を、必ず保存する
✓ できた印2要素認証がオンになり、リカバリーコードを保存した。

ターミナルの開き方と cd（準備2から使う）

事前準備
何のためターミナル ＝ 文字で命令を打つ画面。cd（シーディー）＝ フォルダに入る命令。
  1. Mac：⌘（コマンド）キー＋スペースを押して「ターミナル」と入力し、Enter
  2. Windows：スタートボタンを押して「PowerShell」と入力し、開く
  3. cd Documents で、「書類」（Windows では「ドキュメント」）フォルダに入る（準備8でも使う）
✓ できた印文字を打てる画面が開き、cd Documents を打てた。

準備2　Git と GitHub CLI（gh）を入れる

事前準備
何のためGit ＝ セーブする道具。gh ＝ ターミナルから GitHub を使う道具。

Mac

  1. ターミナルで git --version と打つ
  2. ツールの導入画面が出たら、「インストール」を選ぶ
  3. 入れ終わったら、もう一度 git --version を打つ
  4. gh は https://cli.github.com から入れる

Windows

  1. https://git-scm.com の「Git for Windows」を入れる。インストーラーの質問は、全部そのまま Next
  2. https://cli.github.com の gh を入れる
  3. 入れたあと、PowerShell を開き直す

あわせて Node.js（検査を手元で動かすための道具）も入れておくと便利。任意。入っていなくても、PR の検査で確かめられる。

✓ できた印git --version と gh --version を打って、どちらもバージョンが出ればOK。

準備3　Codex デスクトップアプリを入れる

事前準備
何のためCodex ＝ 作業を手伝ってくれる AI アシスタント。当日は、これに頼む。
  1. https://developers.openai.com/codex/app から、Codex デスクトップアプリを入れる
  2. ChatGPT のアカウントでサインインする
  3. 起動できる状態にしておく

このアプリで、あとの準備8で作業フォルダを選ぶ。頼むときの約束は、準備10で読む。

✓ できた印サインインした状態で Codex が起動し、入力欄が出る。

準備4　ニックネームを決めて、先生に届ける

事前準備
何のためニックネーム ＝ あなたの名札。ファイル名とブランチ名に使う。GitHub のユーザー名は、あとの招待（準備7）に使う。
  1. ニックネームを決める（例：taro-k）
  2. 使える文字は、半角の英小文字・数字・ハイフンだけ
  3. ほかの人と重ならないものにする
  4. 先生が指定する方法で、ニックネームと GitHub のユーザー名を届ける
  5. 先生が、重複がないか確かめる

同じニックネームの人がいると、あとから出した PR が止まってしまう。届けた名前は、当日は変えない（先生から別の名前を頼まれたときだけ、次の準備5の user.name の1行を打ち直す）。

✓ できた印ニックネームとユーザー名を届け、重複がないと確かめてもらった。

準備5（1）メールを非公開にして、noreply を控える

事前準備
何のためセーブ（commit）には、名前とメールアドレスが書き込まれて、公開される。だから先に、メールを公開しない設定にする。
  1. GitHub の画面で、右上のアイコン → Settings → Emails を開く
  2. Keep my email addresses private（メールアドレスを公開しない）にチェックを入れる
  3. 同じ画面に出る noreply アドレス（…@users.noreply.github.com の形。公開しても困らない代わりの住所）を控える。先頭の数字と + もふくめて、まるごと
✓ できた印12345678+taro-k@users.noreply.github.com のような、数字と + のついた noreply アドレスを、まるごとメモに控えた。

準備5（2）名前とメールを Git に登録する

事前準備
何のためセーブ（commit）に書き込まれる名前とメールを、ニックネームと noreply アドレスにしておく。
  1. ターミナルで、名前は準備4のニックネーム、メールは控えたnoreply アドレスにして、次を打つ
  2. < > は消す。" "（ダブルクォート）は残す。例は、次のスライド
  3. 本名や、ふだんのメールアドレスは入れない
git config --global user.name "<ニックネーム>"
git config --global user.email "<控えた noreply アドレス>"
✓ できた印上の2行を打って、エラーが出なかった。

準備5（3）例を見て、入れた値を確かめる

事前準備
何のため< > を消して、" " を残すと、どうなるかを見る。
  1. ニックネームが taro-k のときの例は、次の2行
git config --global user.name "taro-k"
git config --global user.email "12345678+taro-k@users.noreply.github.com"

先生から別のニックネームを頼まれたら、user.name の1行を、新しい名前で打ち直す。

✓ できた印git config --global user.name と git config --global user.email で、入れた値が出ればOK。

準備6　GitHub へのログインを済ませる

事前準備
何のためターミナルから GitHub を使えるように、先にログインしておく。
  1. ターミナルで gh auth login を打って、Enter を押す
  2. 質問は、矢印キーで選んで Enter。選ぶものは、次の4つ（画面は英語）
    GitHub.comHTTPSYesLogin with a web browser
  3. 途中で8文字のコードが出るので、控える。「Press Enter to open github.com in your browser」と出たら、Enter を押す
  4. ブラウザが開いたら、そのコードを貼って Continue。次の画面で Authorize github（許可）を押す
✓ できた印gh auth status で、Logged in to github.com account <ユーザー名> と出る（自分のユーザー名が入る）。

準備7　先生からの招待を承認する

事前準備
何のため先生の共有の棚（リポジトリ kondakaz/zemi-quiz）に、書き込めるようにする。
  1. 先生が、あなたの GitHub のユーザー名あてに、collaborator（共同作業者）の招待を送る
  2. 登録したメールに届く招待メールのリンクから開く
  3. Accept invitation（招待を受ける）を押す

メールが見つからないときは、GitHub の通知か、https://github.com/kondakaz/zemi-quiz/invitations からも開ける。招待には期限（7日）がある。早めに承認する。

✓ できた印https://github.com/kondakaz/zemi-quiz/invitations をもう一度開くと、Accept invitation のボタンがもう出ない。

準備8（1）clone する

事前準備
何のためclone ＝ 共有の棚から、自分の PC に丸ごとコピー。
  1. ターミナルを開き直す（開いた直後は、ホームフォルダにいる）
  2. 次を打つ。cd Documents で「書類」（Windows では「ドキュメント」）フォルダに入ってから、clone する
cd Documents
git clone https://github.com/kondakaz/zemi-quiz.git
cd zemi-quiz
git status

Mac で「"ターミナル"が"書類"フォルダ内のファイルへのアクセスを求めています」のような確認が出たら、「許可」。cd Documents で「見つからない」と出たら、先生に知らせる。

✓ できた印git status に On branch main（いま本番にいる）と出る。ls（中身を表示する命令）で、index.html と questions/ が見える。

準備8（2）pwd のメモと、作業フォルダ

事前準備
何のため当日、cd で迷ったときのために、いまいる場所を控えておく。
  1. clone したターミナルのまま、pwd（いまいる場所を表示する命令）を打つ
  2. 出てきた場所を、メモする（当日、cd で迷ったときに使う）
  3. Codex アプリを起動し、作業フォルダを選ぶところで、メモした場所の zemi-quiz フォルダを選ぶ
✓ できた印pwd の場所をメモした。Codex の作業フォルダに zemi-quiz を選んだ。

準備9　問題の文を考えてくる

事前準備
何のため当日は、メモを写すだけにして、30分に収める。
  1. 問題文
  2. 選択肢4つ（どれも違う文にする）
  3. 正解の番号（0から数える。1つ目が正解なら 0、4つ目なら 3）
  4. 解説（1〜2文）

テーマは自由。Codex に考えてもらってもよいが、答えが本当に正しいかは、自分で確かめる。公開されるので、本名・学籍番号は入れない。

✓ できた印この4つが、メモにそろった。

なぜバージョン管理か
ファイル名で版を分けると、どれが最新か分からなくなる。Git なら、ファイルは1つのまま、セーブが積み重なる。

Git は道具、GitHub は置き場
Git は自分の PC の中で動くセーブ機能。GitHub は、そのセーブをみんなで置く場所。

✓ できた印2つとも、読み終えた。
