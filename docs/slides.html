app.py

ファイルは1つ。

ファイル名に _v2 を付けるのは、今日でやめる。

Git と GitHub は、別のもの

Git（ギット）

記録を取る道具

自分のパソコンの中で動く。
変更を「記録」して、あとで戻せる。
ネットがなくても使える。

GitHub（ギットハブ）

記録を置く場所

インターネット上の置き場。
みんなで共有する。
見合って、直し合える。
サイトも公開できる。

Git は道具、GitHub は置き場。　記録をまとめて入れる場所が「リポジトリ」。

手元と GitHub：4つの動き

commit は手元だけ。　push するまで、GitHub には何も出ない。

ブランチ：main を壊さずに作業する

main には直接 push しない。　ブランチで作って、PR で main に入れる。

Pull Request：見てもらってから、入れる

相互に見て、OK を出し合う。入れるボタンは、作者本人が押す約束。

今日の流れ：9ステップ

手順書にも同じ番号
  1. 1cloneリポジトリを手元に持ってくる
  2. 2ブランチを作るadd-quiz-ニックネーム（先生に届けた名前）
  3. 3問題ファイルを書くquestions/ニックネーム.json

  5. 5GitHub で PR を作る

  7. 7自分の PR を、自分でマージApprove と緑の検査がそろったら
  8. 8サイトで全員の問題を解く1〜2分後
  9. 9main に戻って pull手元にも全員分が来る

公開されるもの：本名は書かない

このリポジトリとサイトは、だれでも見られる。

公開される

・GitHub のユーザー名
・クイズの作者のニックネーム
・commit に残る名前とメール

書かない

・本名
・学籍番号
・メールアドレスなどの個人情報

GitHub Pages：全員の問題がサイトに出る

マージした自分の問題が、そのまま全員のサイトになる。
続けてマージすると、途中の実行が Cancelled になることがある。
最後の実行に全員分が入るので、問題ない。
